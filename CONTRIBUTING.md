# Работа над PrintLab

## Начало работы

1. Установите Node из `.nvmrc`, выполните `npm ci`.
2. Создайте ветку от актуального `main` по номеру задачи, например `SELF-30-printer-list`.
3. Вносите изменения небольшими логически завершёнными частями.
4. Выполните `npm run check`; для изменений интерфейса и маршрутов — `npm run test:e2e`.
5. Откройте PR с описанием поведения и результатов проверки. Изменения интерфейса сопровождайте скриншотами.

## Соглашения

- Файлы и каталоги: `kebab-case`; React-компоненты и типы: `PascalCase`; функции и переменные: `camelCase`.
- Используйте функциональные компоненты и именованные экспорты. Классовый ErrorBoundary — исключение, связанное с API React.
- Используйте `import type` для типов. Не подавляйте TypeScript и ESLint без объяснения причины рядом с исключением.
- Страницы собирают интерфейс, а предметная логика размещается в модулях возможностей. Не переносите код в `shared`, пока у него нет действительно общего назначения.
- Стили компонентов храните в каталоге `styles` соответствующей страницы или возможности, в `*.module.css`. Имена классов — БЭМ: `block`, `block__element`, `block--modifier` или `block__element--modifier`. Общие переменные и базовые стили — в `src/app/styles.css`.
- Страница собирается из компонентов `ui`; состояние и обработчики находятся в `hooks`, чистые преобразования — в `utils`, типы и примеры данных — в `model`. Маленькие компоненты (например, логотип и кнопка) складываются в блоки формы, модели и результатов.
- Логотипы, изображения и иконки интерфейса храните в `src/static`: изображения в `images`, иконки в `icons`, снимки для проверки в `screenshots`. Подключайте ресурсы через импорты Vite. Исходные логотипы из Figma используйте без ручной перерисовки.
- Текст интерфейса сейчас на русском. Код и имена сущностей — на английском. Учитывайте клавиатурную навигацию и семантику HTML.
- Не добавляйте библиотеку «на будущее»: сначала определите реальную задачу, затем оцените размер, поддержку и альтернативы.
- Существующие инструкции форматирования едины для всех. Предпочтения конкретного редактора не должны менять результат.

## Зависимости и окружение

Устанавливайте пакеты через npm. Коммитьте `package.json` вместе с `package-lock.json`; не добавляйте lock-файлы других менеджеров. Обновление Node включает `.nvmrc`, `.node-version`, `engines`, документацию и проверку CI. При смене версии Node заново выполните `npm ci`.

Локальные `.env*` файлы игнорируются, пример `.env.example` хранится в Git. Новую переменную добавляйте в пример, `src/vite-env.d.ts`, модуль `shared/config/env.ts` и документацию. Любое значение `VITE_*` публично; доступ к принтеру с секретами должен проходить через backend.

## Тесты

Vitest + Testing Library проверяют поведение через доступные пользователю роли, названия и действия. Не тестируйте внутреннее состояние компонента или его CSS-классы. Добавляйте проверки важных ошибок и граничных случаев вместе с функцией. Пороги покрытия лежат в `vite.config.ts`; для нового кода расширяйте тесты, а не снижайте пороги.

Playwright проверяет собранное приложение в desktop и mobile Chromium, а Axe — доступность страниц. Новые ключевые пользовательские сценарии добавляйте в `e2e/`. Название приложения в обоих тестовых окружениях закреплено как PrintLab, чтобы локальные `.env` не влияли на проверки. Интеграцию с принтером тестируйте на управляемых заглушках; автоматические тесты не должны запускать настоящую печать.

Husky и lint-staged проверяют подготовленные файлы перед коммитом. Локальные hooks помогают быстро находить ошибки, обязательная полная проверка выполняется в CI. В средах без Git (например, при сборке из архива) зависимости устанавливаются через `HUSKY=0 npm ci`.
