# Архитектура

PrintLab — клиентское SPA с локальным просмотром STL и реальным подбором параметров через `POST /api/optimization/analyze-stl`. Контракт, запуск и границы применимости описаны в [stl-upload.md](stl-upload.md). Протокол подключения принтера пока не определён.

## Направление зависимостей

`app → pages → features → shared`. Возможности просмотра модели и подбора параметров связаны на уровне страницы.

- `app` связывает приложение: маршрутизатор, корневые провайдеры, глобальные стили.
- `pages` содержит страницы. Страницы могут использовать возможности и общие компоненты; не импортируют другие страницы.
- `features/<name>` хранит функциональность: например, подключение принтера или очередь печати. API, состояние, UI и тесты возможности располагаются рядом. Возможности не должны напрямую зависеть друг от друга; их совместную работу координирует страница.
- `shared` содержит общие компоненты и независимые от предметной области инструменты. Не импортирует `features`, `pages` или `app`.

Эти границы — соглашение команды. TypeScript и ESLint проверяют корректность кода, но отдельного автоматического правила архитектурных импортов сейчас нет. Если сложность вырастет, это правило можно добавить отдельно.

## Состояние и сеть

STL и геометрия остаются в памяти `features/model-viewer`. Сетевой контракт и проверка ответа находятся в `features/optimization/api/optimization.ts`. Hook расчёта блокирует повторную отправку, отменяет устаревший запрос и сбрасывает результат при изменении параметров. Страница передаёт выбранный файл в расчёт; возможности не импортируют друг друга. Общие сообщения ошибок файла находятся в `shared/api/errors.ts`. Периодических запросов, автоматических повторов и глобального store нет.

## Маршруты и ошибки

`AppRoutes` определяет маршруты `/` и `*`. BrowserRouter использует базовый путь Vite. Новый маршрут добавляется вместе с тестом прямого открытия и пользовательской навигации.

Корневой ErrorBoundary перехватывает ошибки рендера и показывает возможность перезагрузки, не выводя технические подробности. Он не перехватывает ошибки обработчиков событий и отклонённые сетевые запросы: эти состояния обрабатываются рядом с соответствующей операцией. Для будущих больших экранов можно добавить локальные границы и ленивую загрузку.

## Стили и настройки

CSS Modules изолируют стили, общие CSS-переменные задают начальные цвета. Используется системный шрифт без внешней загрузки. Настройки окружения читаются централизованно в `shared/config/env.ts`, чтобы компоненты не зависели от отдельных переменных Vite.

## Инструменты

TypeScript проверяет приложение и конфигурацию через отдельные проекты. ESLint использует правила с информацией о типах и React Hooks. Prettier отвечает за форматирование. Vitest повторно использует плагины и alias Vite; Playwright работает с production-сборкой, а не с dev-сервером. Axe проверяет доступность главной страницы и страницы 404 в реальном браузере.
