# STL и реальный подбор параметров

## Совместный запуск

Нужны JDK 25 и Node.js из `.nvmrc`.

Backend:

```sh
./mvnw test
./mvnw spring-boot:run
```

Frontend:

```sh
nvm use
npm ci
npm run dev
```

Откройте <http://localhost:5173>. Vite перенаправляет `/api` на `http://127.0.0.1:8080`. Для другого адреса: `API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev`. Переменная читается из окружения процесса Vite. Proxy работает также в preview; при размещении сайта перенаправление настраивается веб-сервером (см. `deployment.md`).

## Пользовательский сценарий и сетевые запросы

1. Выбор STL, проверка базовой структуры, просмотр, вращение, масштабирование и удаление из просмотра происходят локально. Файл не отправляется на сервер и не сохраняется в `localStorage`.
2. Кнопка расчёта отправляет один `POST /api/optimization/analyze-stl` с исходным файлом и параметрами формы.
3. Пока запрос выполняется, повторная отправка заблокирована. Изменение модели или параметров отменяет ожидание предыдущего запроса и очищает устаревший результат.
4. Успешный результат остаётся на странице, а кнопка становится недоступной до изменения условий. Ввод параметров не запускает фоновых пересчётов. Автоматических повторов и опроса сервера нет.
5. Ошибка не удаляет локальную модель: пользователь может исправить условия и явно повторить запрос. Ожидание сервера ограничено минутой.

Отмена запроса браузером не гарантирует остановку уже начавшейся обработки на сервере. Постоянное хранение не участвует в этом сценарии: endpoint расчёта читает временный multipart-файл, но не записывает модель в `data/uploads`. Старые API `POST /api/models` и `GET /api/models/{id}` сохранены для явного сохранения; текущий интерфейс их не вызывает. Ранее сохранённые файлы автоматически не удаляются.

Файл и результат живут в памяти страницы до обновления или закрытия. Интерфейс не обещает сохранение проекта или истории.

## Ручная проверка реального результата

Выберите `fixtures/cube-20.stl` и задайте:

- материал PLA;
- нагрузку 40 Н, коэффициент запаса 2;
- испытание «Изгиб», слой 0,2 мм;
- приоритет минимального расхода;
- периметры и ориентацию — «Подобрать», ограничения времени и материала — пустые.

В текущих данных backend выберет 15% заполнения, 13,74 г, 36 минут и нагрузку с запасом 40,45 Н. При изменении нагрузки на 45 Н результат меняется на 30%, 18,72 г, 44 минуты и 46,58 Н. Это данные из `printlab-backend/data/experiments.json`, а не фиксированный пример интерфейса.

С исходной нагрузкой 100 Н подходящих вариантов нет. Для произвольного STL, PETG или испытания на сжатие текущих данных также может не быть: интерфейс объясняет причину и не показывает выдуманные цифры.

## Границы применимости

Backend сопоставляет STL с исследованным образцом по объёму, площади поверхности и каждой стороне ограничивающего параллелепипеда: отклонение каждого показателя не больше 1%. Это проверка геометрических признаков, не доказательство одинаковой формы или прочности. В результате всегда показаны образец и границы применения испытаний.

После отбора модели, материала, типа испытания и параметров печати алгоритм проверяет нагрузку, ограничения времени и массы. Допустимая нагрузка в сравнении равна измеренной силе разрушения, делённой на коэффициент запаса. Затем выбирается минимальная масса, минимальное время, максимальная измеренная нагрузка или сбалансированный показатель. Новые конфигурации и прочность произвольных деталей не прогнозируются. График показывает только измеренные варианты, без интерполяции.

## API расчёта

`POST /api/optimization/analyze-stl`, `multipart/form-data`. Поле `file` содержит исходный STL. Остальные поля:

| Поле                                            | Значение                                               |
| ----------------------------------------------- | ------------------------------------------------------ |
| `material`                                      | PLA, PETG, ABS                                         |
| `requiredLoadN`                                 | Положительная нагрузка, Н                              |
| `safetyFactor`                                  | От 1 до 10                                             |
| `priority`                                      | MIN_WEIGHT, MIN_TIME, MAX_STRENGTH, BALANCED           |
| `maxPrintTimeMin`, `maxMaterialConsumptionG`    | Ограничения; 0 — отсутствуют                           |
| `layerHeightMm`, `perimeters`                   | Параметры печати; 0 — подобрать                        |
| `infillPattern`, `printOrientation`, `testType` | Строковые фильтры; пустая строка не ограничивает выбор |

Браузер сам задаёт `Content-Type` с multipart boundary. Успешный ответ содержит выбранные параметры, `loadCapacityN`, сопоставленный образец, объяснение, предупреждения и массив `experiments` для графика и таблицы. Frontend проверяет структуру ответа до отображения.

Ошибки имеют HTTP-статус и понятный `code`: `MODEL_NOT_SUPPORTED`, `NO_EXPERIMENTS`, `NO_SUITABLE_CONFIGURATION` (422), `INVALID_CALCULATION_INPUT` (400), а также ошибки STL и превышения размера (413). Исходные технические сообщения в интерфейс не выводятся.

## STL и предпросмотр

Поддерживаются ASCII и бинарный STL до 15 МиБ (15 728 640 байт), до 100 000 граней. Backend повторно проверяет структуру, конечные координаты с модулем до 10¹² и невырожденные треугольники. Сам STL не задаёт единицы измерения; приложение принимает координаты за миллиметры.

Three.js/WebGL 2 рисует все треугольники, без прореживания, обводок и просвечивания внутренних стенок. Освещение и нормали сглаживают округлые поверхности, сохраняя резкие углы и координаты вершин. В области просмотра нет текстовых подсказок и технических счётчиков. Доступны вращение мышью/пальцем, колесо/щипок, кнопки и клавиатура (стрелки, «+»/«−», Home). Ресурсы сцены освобождаются при замене модели и уходе со страницы.

## Проверки

```sh
npm run check
npm run test:e2e
# С запущенным backend:
E2E_BACKEND=1 npm run test:e2e
```

Браузерные проверки с backend подтверждают отсутствие запросов при выборе STL, один запрос по кнопке, реальные результаты для разных нагрузок и понятные ответы при отсутствии данных. Не запускайте одновременно `npm run check` и браузерные тесты: обе команды пересобирают одну папку `dist`.

## Материалы из справочника

Список материалов загружается с `GET /api/materials`; в интерфейсе больше нет отдельного
списка PLA/PETG/ABS. Справочник содержит восемь конкретных продуктов, ссылки на паспорта
и условия измерений. Блок «Свойства материала и источник» по умолчанию свёрнут.
Запрос объединяется между компонентами и кешируется на час, без фоновых повторов.
При ошибке можно явно повторить загрузку; предварительный просмотр STL остаётся доступен.

При расчёте отправляются `materialProfileId` и семейство `material`. Паспортные свойства
материала не подставляются вместо испытаний детали. Для неподтверждённой комбинации
остаётся понятная ошибка; наличие паспорта ещё не означает доступность расчёта нагрузки.
Тестовый `src/test/material-catalog.json` — снимок API для автономных проверок интерфейса,
а не второй рабочий справочник. При изменении схемы или данных обновите этот снимок.

## Подбор параметров печати для любой подходящей модели

По умолчанию открывается режим «Параметры печати · A1 mini». Он использует настоящий
Bambu Studio на бэке и работает для STL вне базы исследованных образцов. Профиль:
A1 mini, сопло 0,4 мм, текстурированная PEI-пластина; материалы PLA, PETG и TPU 95A.
Время и расход обозначены как оценки. Допустимая нагрузка в этом режиме не выводится.

Файл отправляется одним запросом `POST /api/print-plans/analyze-stl` только после нажатия
кнопки. Сравниваются шесть комбинаций слоя, заполнения и периметров; пользователь задаёт
их минимумы/качество, поддержки, приоритет и ограничения. Результат содержит метрики,
тип заполнения и сравнение вариантов. Изменение параметров сбрасывает результат и
отменяет ожидание предыдущего запроса, повторные нажатия блокируются. Автоматических
повторов при занятости или ошибке нет. Бэк кеширует одинаковые успешные расчёты.

Второй режим — «Нагрузка по испытаниям образцов» — сохраняет прежний подбор по физическим
испытаниям. Справочник свойств материалов общий для обоих режимов. Вращение модели
в просмотре меняет камеру и не поворачивает STL для печати.

`fixtures/stepped-block.stl` — L-образная деталь 30 × 30 × 15 мм вне базы образцов.
Для настоящей интеграционной проверки запустите бэк с Bambu Studio, затем:

```sh
E2E_BACKEND=1 E2E_BAMBU=1 npm run test:e2e -- --workers=1
```

Файл `src/test/print-plan-response.json` — контролируемый ответ для автономных тестов;
он не подключается к приложению. Проверка с `E2E_BAMBU=1` обращается к настоящему бэку.
