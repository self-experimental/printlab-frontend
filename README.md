# PrintLab

React-приложение для работы с 3D-печатью. На этом этапе подготовлен фундамент: сборка, маршрутизация, обработка ошибок и инструменты командной разработки. Подключение принтера и бизнес-функции будут добавляться отдельными задачами.

STL открывается локально в 3D-просмотре. По кнопке расчёта файл и параметры отправляются на Spring Boot; карточка, график и таблица показывают реальные результаты подбора по экспериментам. Совместный запуск, тестовый куб и границы применимости: [docs/stl-upload.md](docs/stl-upload.md).

## Быстрый старт

Нужен **Node.js 24.19.0** и npm **10.8.2–12.x**. Версия Node закреплена в `.nvmrc` и `.node-version`, ограничения проверяются при установке. Для команд в терминале переключите Node через `nvm use`.

```sh
nvm install
nvm use
npm ci
npm run dev
```

Если используете другой менеджер Node, установите версию из `.node-version`. `nvm` не является зависимостью проекта.

Приложение: <http://localhost:5173>. Если порт занят, сервер сообщит об этом; другой порт можно указать через `npm run dev -- --port 5174`.

Обязательных переменных окружения нет. Для локальных настроек скопируйте `.env.example` в `.env.local`. После изменения переменных перезапустите сервер. `VITE_APP_NAME` меняет название приложения и заголовок вкладки; по умолчанию используется PrintLab.

Все `VITE_*` переменные попадают в браузерную сборку. Пароли, ключи принтера и другие секреты должны храниться на стороне будущего backend.

## Команды

| Команда                 | Назначение                                                    |
| ----------------------- | ------------------------------------------------------------- |
| `npm run dev`           | Разработка с быстрым обновлением интерфейса                   |
| `npm run build`         | Проверка TypeScript и production-сборка в `dist/`             |
| `npm run preview`       | Локальный просмотр готовой сборки на порту 4173               |
| `npm run typecheck`     | Проверка типов приложения, тестов и конфигурации              |
| `npm run lint`          | ESLint: типы и React Hooks, без предупреждений                |
| `npm run lint:fix`      | Автоматическое исправление поддерживаемых правил              |
| `npm run format`        | Форматирование файлов проекта                                 |
| `npm run format:check`  | Проверка форматирования                                       |
| `npm test`              | Однократный запуск тестов компонентов и модулей               |
| `npm run test:watch`    | Тесты в режиме наблюдения                                     |
| `npm run test:coverage` | Тесты с порогами покрытия и HTML-отчётом в `coverage/`        |
| `npm run test:e2e`      | Браузерные тесты production-сборки: desktop и mobile Chromium |
| `npm run test:e2e:ui`   | Интерактивный интерфейс браузерных тестов                     |
| `npm run check`         | Форматирование → lint → тесты с покрытием → типы и сборка     |

Для браузерных тестов один раз установите Chromium:

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright самостоятельно собирает приложение и запускает preview. Порт 4173 должен быть свободен. Браузерные тесты запускаются отдельно от `check`, поскольку требуют установки браузера.

## Стек и структура

React + TypeScript в строгом режиме, Vite, React Router, CSS Modules. npm — единый менеджер зависимостей; точные версии и `package-lock.json` обеспечивают воспроизводимую установку через `npm ci`.

```text
src/
  app/             # Корневой компонент, провайдеры, маршруты, глобальные стили
  pages/           # Компоненты страниц и их локальные стили
  shared/
    config/        # Типизированные настройки окружения
    ui/            # Общие компоненты, включая ErrorBoundary
  test/            # Общая настройка тестового окружения
  main.tsx         # Точка входа
e2e/               # Браузерные сценарии
public/            # Статические файлы без обработки сборщиком
```

Импорты от `@/` указывают на `src/` и одинаково работают в TypeScript, Vite и Vitest. Тесты `*.test.ts(x)` лежат рядом с проверяемым кодом. Общие правила: [CONTRIBUTING.md](./CONTRIBUTING.md), развитие структуры: [docs/architecture.md](./docs/architecture.md).

При открытии проекта VS Code предложит ESLint, Prettier и EditorConfig. Включены форматирование при сохранении и исправление ESLint. Используйте рабочую версию TypeScript из проекта.

## Проверки команды

`npm ci` подключает Husky. Перед коммитом lint-staged проверяет и форматирует только подготовленные к коммиту файлы. Это короткая локальная проверка; полный `npm run check` и браузерные тесты выполняются в GitHub Actions для каждого PR и изменений `main`. В CI сохраняется артефакт сборки, при падении браузерных тестов — отчёт, скриншоты и трассировки.

При коммите из VS Code хук может получить старый Node из окружения редактора. Хук сначала
проверяет текущую версию, а при необходимости использует установленную через NVM версию
из `.nvmrc` (`NVM_DIR` или стандартный `~/.nvm`). Он не меняет глобальные настройки Node.
Если нужная версия не найдена, коммит останавливается с понятной инструкцией
`nvm install && nvm use`. Для других менеджеров Node нужна подходящая версия в `PATH` редактора.

Dependabot проверяет npm-зависимости и GitHub Actions еженедельно. Обновления проходят те же проверки. Защиту ветки `main` и обязательные статусы CI нужно включить в настройках репозитория GitHub.

## Сборка и размещение

```sh
npm ci
npm run build
npm run preview
```

Публикуется содержимое `dist/`. `preview` служит для локальной проверки; для размещения используйте статический хостинг. Сервер должен возвращать `index.html` для маршрутов приложения, сохраняя обычную обработку файлов ресурсов: маршрутизация выполняется в браузере. Пример конфигурации Nginx приведён в [docs/deployment.md](./docs/deployment.md).

По умолчанию приложение размещается в корне домена. Для подкаталога соберите с `npm run build -- --base=/printlab/` и настройте сервер на тот же префикс. Router использует Vite `BASE_URL`. Переменные окружения задаются **до сборки**; изменение окружения уже размещённых статических файлов не изменит приложение. Sourcemaps production-сборки отключены.
